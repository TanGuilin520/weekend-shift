# 周末单 · 大学生周末兼职撮合平台（交互原型）

> 把「大学生周末想赚生活费」和「校园周边 3 公里商家周末临时缺人」在 24 小时内撮合完成。

**纯前端交互原型**：零依赖、零构建，双击 `index.html` 即可运行，也可直接部署到 GitHub Pages / 任意静态托管。

---

## 它是什么

这不是设计稿，是一个**能点、能跑通完整交易闭环**的可交互原型：

- **三端互通**：学生端 / 商家端 / 平台管理端共用同一份数据，切个身份就能看到同一笔订单的另一面
- **真实业务逻辑**：7 维加权匹配算法、订单状态机、信用分增减、资金托管结算、双向盲评、审核与纠纷仲裁
- **一键演示**：右侧控制台点「执行下一步」，12 步自动走完 `报名 → 录用 → 签到 → 签退 → 确认工时 → 结算 → 评价`，最后落到平台北极星指标
- **数据可重置**：所有状态存 localStorage，随时点「重置演示数据」回到初始

## 匹配算法

原型真实实现了 PRD 中的加权模型（见 `assets/data.js` 的 `matchScore`）：

```
MatchScore = 0.25 × 时间匹配度      // 岗位时间片与学生空闲时段的交集占比
           + 0.20 × 距离得分        // 1 - 距离/3km
           + 0.15 × 信用得分        // 信用分 / 1000
           + 0.15 × 履约得分        // 完成单数 / (完成 + 爽约×3 + 取消)
           + 0.10 × 技能标签匹配
           + 0.10 × 薪资匹配
           + 0.05 × 活跃度
           + 关系加分（同商家复购 +8，复购≥2 次再 +4）
           − 惩罚项（取消、爽约按次扣减）
```

**硬性过滤**（先于打分，命中即不可报名并说明原因）：

1. 未完成实名 + 学生认证 → 需先认证
2. 与空闲时段零交集 → 时间冲突
3. 信用分低于岗位门槛
4. 距离超过学生设置上限
5. 在途订单已达 3 单
6. 岗位名额已满

选中不同学生账号（林小雨 735 分 / 陈子豪 620 分 / 周晓萌未认证），同一批岗位的匹配结果和可报名状态会明显不同。

## 演示动线建议

1. **学生端**（林小雨）→ 看匹配度诊断 → 报名
2. **商家端**（巷子口老火锅）→ 处理报名 → 录用
3. **学生端** → 日程 → 扫码签到 → 签退
4. **商家端** → 确认工时 → 结算
5. **学生端** → 钱包到账 → 评价商家
6. **平台端** → 审核「深夜烧烤吧」入驻 → 处理工单 → 看北极星指标

## 说明与边界

- 这是**产品原型**，不是生产系统：没有后端、没有真实支付、没有真实定位与人脸核验，相关环节均为模拟。
- 数据仅存浏览器 localStorage，不会上传任何服务器。
- 配套的产品设计文档见 [docs/PRD.md](docs/PRD.md)，包含可行性假设、冷启动、商业化、合规与路线图。
