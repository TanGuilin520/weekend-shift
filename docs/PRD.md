## 0. 前置假设与边界

因需求方未给定具体城市、预算与团队规模，以下为**沿用假设**，后续可整体替换而不影响产品结构：

| 编号 | 假设项 | 假设内容 |
| --- | --- | --- |
| A1 | 试点城市 | 二线/新一线城市的高校聚集区（如武汉光谷、成都温江、西安长安区、郑州龙子湖） |
| A2 | 单校规模 | 试点高校在校生 1.5 万–4 万人，其中约 35% 有周末兼职意愿 |
| A3 | 周边供给 | 校区 3 公里内可触达商家 300–800 家，其中周末存在短期用工缺口的约 20% |
| A4 | 订单形态 | 单次 4–8 小时，时薪 15–30 元，单笔订单金额 80–240 元 |
| A5 | 用工高峰 | 周五 18:00 至周日 22:00；旺季为开学季、节假日、店庆、大促、展会季 |
| A6 | 团队规模 | MVP 团队 1 产品 + 1 设计 + 3 研发 + 2 运营 + 2 BD |
| A7 | 法律定性 | 在校生勤工助学/短期劳务**不构成劳动关系**，平台定位为**信息撮合与交易服务方**，不直接雇佣学生 |
| A8 | 年龄范围 | 仅开放**年满 18 周岁**在校生（含研究生），16–18 岁不开放 |
| A9 | 载体 | 主端为微信小程序（学生/商家），管理端为 Web 后台 |
| A10 | 支付 | 商家在线支付到平台，履约确认后结算给学生（资金托管） |

**明确不在本文档范围内**：数据库设计、API 设计、技术选型、部署架构、算法工程实现、UI 视觉稿。

## 1. 项目名称与一句话定位

### 1.1 三个候选项目名

| 候选名 | 含义 | 风格 |
| --- | --- | --- |
| **周末单**（推荐） | 「周末 + 接单」，直白、口语化、易传播 | 校园口语 |
| **校边工社** | 「校园周边的用工合作社」，强调地域与信任 | 稳重、偏 B 端 |
| **搭个班** | 「搭个班一起上班」，强调组队与轻社交 | 年轻、社交向 |

**最终推荐：周末单**。理由：学生只需理解「周末有单可接」，商家只需理解「周末有人可叫」，命名即价值主张，且小程序搜一搜的语义直观。

### 1.2 一句话定位

> **周末单**：把「大学生周末想赚生活费」和「校园周边 3 公里商家周末临时缺人」在 24 小时内撮合完成，用实名认证、资金托管与双向信用分解决「找不到、不敢去、来了跑、结不了账」四件事。

### 1.3 一句话价值主张（分端）

- 对学生：**离得近、时间合得上、钱有保障、出事有人管。**
- 对商家：**发单有人来、来的人靠谱、工时结算清楚、不用自己管招聘。**

## 2. 目标用户与核心痛点

### 2.1 大学生端

**典型画像**

| 画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| 生活费敏感型（大一/大二） | 月生活费 1500–2500 元，时间充裕，无技能标签 | 门槛低、离家(校)近、当场结 |
| 技能变现型（大二/大三） | 有摄影、主持、设计、外语、带货等技能 | 高时薪、能写进简历 |
| 攒钱目标型（大三/大四） | 有明确目标（考证、旅游、设备） | 稳定复购、长期固定岗 |

**需求清单**

1. 找到**周末当天可做、通勤 ≤ 40 分钟**的岗位。
2. 明确知道：时薪、总工时、结算时间、是否包餐、要不要健康证。
3. 不被中介收费，不被拖欠工资，不被临时放鸽子。
4. 不因兼职影响上课与考试（时间冲突可控）。
5. 出安全事故或纠纷时，有平台介入。

**痛点（按被吐槽频次排序）**

| 优先级 | 痛点 | 现状 |
| --- | --- | --- |
| 高 | 信息分散且过期 | 微信群/QQ 群刷屏、贴吧帖子陈旧、闲鱼信息零散 |
| 高 | 真假难辨，中介收费与诈骗 | 「先交 200 押金」「刷单返利」「培训贷」高发 |
| 高 | 薪资拖欠与口头承诺 | 干完说「下周结」，然后失联 |
| 高 | 商家爽约/临时取消 | 到店被通知「人够了」 |
| 中 | 匹配效率低 | 翻 100 条信息，符合时间与距离的只有 3 条 |
| 中 | 通勤成本被低估 | 单程 1 小时、时薪 18 元，实际时薪腰斩 |
| 中 | 无履历沉淀 | 做过的兼职无法证明，无法用于简历或换取更好岗位 |
| 低 | 无同伴、安全感不足 | 尤其是夜间或陌生场地岗位 |

**使用动机**：赚生活费 > 攒特定目标 > 积累经验/技能 > 打发时间与社交。

### 2.2 商家端

**典型画像**

| 画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| 餐饮小店（火锅/烧烤/奶茶/快餐） | 周末客流翻 1.5–3 倍，店员请假多 | 周六早上前补 1–2 人，能干活就行 |
| 连锁零售门店（3C、美妆、运动） | 大促/店庆需促销员 | 形象与表达能力，需筛选 |
| 活动执行方（展会、路演、赛事） | 单日 50–300 人集中用工 | 批量到岗、统一管理、当天结算 |
| 本地服务商（搬家、地推、物料） | 项目制、临时性强 | 急招、可接受日结 |

**需求清单**

1. 30 分钟内发布岗位，24 小时内有人确认到岗。
2. 看到报名者的**可信身份**（在校证明、信用分、历史评价）。
3. 到岗率可控，爽约有人替补。
4. 工时与结算线上化，少扯皮、少现金。
5. 有争议时平台给判定依据。

**痛点**

| 优先级 | 痛点 | 现状 |
| --- | --- | --- |
| 高 | 周末临时缺人没有专门渠道 | 58/兼职猫偏长期，微信群靠人情和运气 |
| 高 | 到岗率低、临时放鸽子 | 口头约定无约束，学生一句「来不了」就结束 |
| 高 | 筛选成本高 | 简历信息为零，无法判断能不能用 |
| 中 | 结算与考勤混乱 | 纸质签到、现金日结、口头工时，易起纠纷 |
| 中 | 发布后无人响应 | 帖子沉底、被群消息淹没 |
| 中 | 学生无经验、需手把手教 | 培训成本高于用工价值 |
| 低 | 重复招人耗时 | 每次都要重新发一遍、重新聊一遍 |

**使用动机**：解决**确定性的短期缺人** > 降低招聘与管理成本 > 避免劳动用工风险。

### 2.3 平台端需要解决的核心问题

| 问题域 | 具体问题 | 平台对策方向 |
| --- | --- | --- |
| 双边冷启动 | 无岗位则学生不来，无学生则商家不发 | 单校单商圈、先锁岗位池再拉学生（见第 9 章） |
| 供需时间错配 | 商家要「明天早上 9 点」，学生要「周六下午」 | 以**时间片**为核心匹配维度，而非岗位为唯一维度 |
| 双向信任 | 学生怕被骗，商家怕被放鸽子 | 实名认证 + 资金托管 + 双向信用分 + 履约保证金 |
| 履约不可控 | 到岗、工时、完成质量全靠线下 | 定位签到签退 + 商家确认 + 双向评价 + 争议仲裁 |
| 信息真实性 | 虚假岗位、传销、刷单 | 商家资质审核 + 岗位审核 + 敏感词与黑名单 |
| 安全与合规 | 意外伤害、未成年人、税务 | 按单投保 + 年龄门槛 + 灵活用工合规结算 |
| 网络效应 | 单城市单校易被替代 | 沉淀信用资产与固定班底关系，提高迁移成本 |

## 3. 典型使用场景

### 场景一：商圈火锅店周六晚高峰帮工（餐饮帮工）

- **背景**：大学城商业街某火锅店，周六 17:00–22:00 需临时增加 2 名服务员/传菜员，时薪 22 元，包工作餐。
- **学生路径**：
  1. 周四晚打开小程序首页，看到「距你 800m｜周六 17:00–22:00｜22 元/时｜火锅店传菜」。
  2. 系统显示「时间匹配 100%｜信用要求 600+｜需健康证：否」。
  3. 点击「立即报名」，上传一张生活照，填写「有餐饮经验 1 次」。
  4. 15 分钟后收到录用通知，日程自动写入「我的日程」，同时收到地址、联系人虚拟号、着装要求。
  5. 周六 16:55 到店，扫商家二维码签到（定位校验在 200m 内）。
  6. 22:05 签退，商家确认工时 5 小时。
  7. 平台 T+1 结算 110 元到微信零钱，并弹出「评价商家」。
- **商家路径**：
  1. 周五 10:00 在商家端发布岗位（模板选择「餐饮-传菜」，填时间、人数、时薪、要求）。
  2. 系统推荐 12 名匹配学生，商家批量查看信用分与评价。
  3. 录用 2 人，未录用者自动收到「本次已招满，已加入候补」。
  4. 学生签到后商家端显示「已到岗 2/2」，签退时确认工时。
  5. 对 2 人分别评价，其中 1 人加入「我的班底」，下次可一键邀请。
- **平台动作**：岗位审核 → 匹配推送 → 到岗提醒（提前 2 小时）→ 签到监控 → 工时确认 → 自动结算 → 双向评价。

### 场景二：城市马拉松/车展单日活动协助（展会活动）

- **背景**：周六城市马拉松，赛事服务商需 120 名物料发放与引导人员，6:00–14:00，日薪 180 元，需统一集合。
- **学生路径**：
  1. 通过「活动专区」看到「日薪 180 元｜含早餐与交通补贴｜需凌晨 5:20 集合」。
  2. 报名时需阅读并勾选《活动须知》，确认可接受早班与集合点。
  3. 被录用后收到**集合点导航 + 带队人联系方式 + 行程分享卡片**（可分享给紧急联系人）。
  4. 现场由带队人批量扫码签到；活动结束签退。
  5. 次日收到结算与「活动证书/履历记录」，可一键生成兼职履历。
- **商家路径**：
  1. 使用「批量用工」发布：需求 120 人，设置 3 个岗位分组（引导/物料/补给）。
  2. 后台看到报名 260 人，按「信用分 + 履约率 + 是否做过同类活动」排序，一键批量录用 120 人。
  3. 通过「批量通知」推送集合信息；活动当天在管理端看实时到岗率。
  4. 结算按整体订单一次性确认，并给优秀者打标签。
- **平台动作**：大额订单预付款托管 → 批量录用工具 → 到岗率看板 → 异常缺岗自动触发候补补位（从候补池拉人）。

### 场景三：校园周边 3C 门店新店开业促销（零售促销）

- **背景**：商场内某品牌门店新店开业，周六周日两天各需 3 名促销员，时薪 25 元 + 销售提成，要求表达清晰、形象良好。
- **学生路径**：
  1. 在筛选器中选择「时薪 ≥ 25」「距离 ≤ 2km」「技能标签：促销/沟通」，得到 6 条结果。
  2. 查看岗位详情：工作内容、提成规则、是否需要正装、午餐是否提供。
  3. 报名后商家发起**视频/语音简单沟通**（平台内 5 分钟通话，不暴露手机号）。
  4. 被录用后参加 15 分钟线上培训（图文卡片 + 3 道小测）。
  5. 两天分别签到签退，商家确认工时与提成。
  6. 结算后获得「零售促销」技能标签与经验值。
- **商家路径**：
  1. 发布岗位并开启「需要筛选」，设置 3 个硬性条件（可周末两天连做、有促销经验、能接受站立 8 小时）。
  2. 查看报名列表，使用「在线沟通」确认意向，录用 3 人并拒绝其余。
  3. 上传培训材料，绑定岗位，到店确认工时与提成金额。
- **平台动作**：标签体系推荐 → 在线沟通（隐私号/IM）→ 培训小测完成度校验 → 提成结算争议通道。

### 场景四：校园内部活动执行（校内勤工助学补充）

- **背景**：学院运动会、招聘会、社团招新需要 10 名现场协助，学校给 100 元/天补贴。
- **学生路径**：在「校内专区」报名，需求方为**校园组织认证账号**（学生会/社团/学院），信任度高，通常秒录用。
- **商家（校园组织）路径**：以「校园组织」身份认证，发布岗位，使用免费额度。
- **平台动作**：此类订单**不抽佣**，用于提高学生日活与信任，是重要的冷启动燃料。

### 场景五：周末快递/倉储分拣高峰（谨慎开放）

- **背景**：周末电商小高峰，区域分拣中心需 30 名分拣临时工，18:00–24:00。
- **特殊规则**：夜间岗位强制要求 **18 周岁以上 + 信用分 650 以上 + 历史履约 ≥ 2 次**；强制开启行程分享；平台按单投保意外险。
- **平台动作**：夜间与重体力岗位走高门槛白名单机制，宁缺毋滥。

## 4. 核心业务流程

### 4.1 学生找兼职流程

```
注册 → 微信一键登录 → 实名认证（身份证+人脸）→ 学生身份认证（学信网/学生证/校园邮箱 三选一）
  → 完善档案（校区、可工作时段、通勤方式、技能标签、期望时薪）
  → 首页推荐 / 搜索筛选 / 订阅提醒
  → 岗位详情（薪资、时间、距离、要求、信用门槛、是否需健康证）
  → 报名（可附一句话自我介绍 + 相关经验）
  → 等待录用 / 即时抢单成功
  → 录用通知 + 日程写入 + 到岗提醒（T-24h、T-2h）
  → 到店扫码签到（定位校验）→ 工作中（一键求助可用）
  → 签退 → 商家确认工时 → 平台结算到零钱（T+1）
  → 双向评价 → 信用分与技能标签更新 → 进入下一次推荐
```

**关键规则**

- 报名人数上限：每个学生同时「已录用未完成」的订单不超过 **3 单**，避免超售。
- 时间冲突校验：报名时若与已录用订单时间重叠，需二次确认或禁止报名。
- 撤回规则：开始前 ≥ 12 小时可无损取消；< 12 小时取消扣信用分 5 分并计入履约记录。

### 4.2 商家发兼职流程

```
注册 → 手机号+微信登录 → 商家认证（营业执照 / 门店照片 / 法人身份证 / 门店定位打卡）
  → 平台审核（1 个工作日内，MVP 人工审核）
  → 发布岗位（选择模板 → 填时间片、人数、时薪、结算方式、要求、是否需面试）
  → 岗位审核（敏感词 + 薪资下限校验 + 类目黑名单）
  → 上线并触发匹配推送（按时间片向匹配学生推送/展示）
  → 报名收集 → 筛选（按信用分/履约率/标签/经验）→ 录用/拒绝 → 发送录用与到岗须知
  → 签到监控（实时到岗率看板）→ 缺岗自动候补补位
  → 签退确认工时（超时未确认，T+24h 自动按签到记录确认）
  → 支付（托管资金解冻 + 平台服务费）→ 评价学生 → 加入班底
```

**关键规则**

- 薪资下限校验：低于当地最低小时工资标准或低于平台该类目建议价 70% 的岗位，**直接拒审**并提示。
- 拒绝必须选理由（经验不足/已招满/距离过远/其他），理由对学生可见，避免「已读不回」。
- 录用后商家取消：需支付 **20% 补偿金给学生**并从商家账户扣除，同时扣商家信用分。

### 4.3 平台撮合流程

```
岗位发布 → 结构化解析（时间片 / 地点 / 类目 / 技能 / 薪资 / 门槛）
                     ↓
        匹配引擎（规则过滤 → 打分排序 → 曝光分配）
                     ↓
      ┌──────────────┼──────────────┬───────────────┐
   抢单模式        报名模式        邀请模式        派单模式
 (先到先得)   (商家筛选录用)  (商家定向邀约)  (平台客服人工撮合急单)
      └──────────────┼──────────────┴───────────────┘
                     ↓
             录用确认 / 双向通知
                     ↓
        到岗提醒（T-24h 名单确认 → T-2h 出发提醒）
                     ↓
              履约与结算闭环
                     ↓
        数据回流：信用分、履约率、标签、匹配权重迭代
```

**模式选择原则**（详见 7.4）：

- 标准化、低门槛、急招岗位 → **抢单**；
- 需筛选、有形象/技能要求 → **报名 + 录用**；
- 高信用学生与复购商家 → **邀请**；
- 大额/特殊/无人应招 → **平台派单（人工兜底）**。

### 4.4 履约、签到、结算、评价、投诉流程

| 环节 | 触发 | 主要动作 | 异常与兜底 |
| --- | --- | --- | --- |
| 名单确认 | T-24h | 系统向学生确认「能否到岗」，向商家同步名单 | 学生未确认 → 自动列入风险，推送候补学生 |
| 出发提醒 | T-2h | 推送地址、导航、着装、联系人虚拟号 | 学生标记「无法到岗」→ 立即触发候补补位 |
| 签到 | 到岗时 | 扫商家二维码 + 定位校验（≤200m）+ 人脸可选 | 定位失败/二维码异常 → 上传现场照片 + 商家手动确认 |
| 签退 | 离岗时 | 扫码签退 + 填写实际工时 | 忘记签退 → 商家可手动补录；双方不一致 → 进入工时仲裁 |
| 工时确认 | 签退后 | 商家确认工时与最终金额 | T+24h 商家未确认 → 按学生签到记录自动确认 |
| 结算 | 确认后 T+1 | 平台解冻托管资金，打款至学生微信零钱 | 提现失败 → 余额留存并通知；争议中 → 冻结该笔金额 |
| 评价 | 结算后 48h 内 | 双向盲评（互不可见），48h 后同时公开 | 到期未评价 → 视为默认好评并计入完成率 |
| 投诉 | 履约任意阶段 | 学生/商家均可发起，选择类型并上传证据 | 24h 内客服响应，72h 内出结论 |

**投诉处理机制**

1. **分级**：轻微（工时 1 小时内差异）→ 系统按规则自动判定；一般（工时/态度/放鸽子）→ 客服 1 对 1 调解；严重（诈骗、性骚扰、人身安全、名誉）→ 风控介入，先冻结账号，必要时移交公安。
2. **证据要素**：签到定位记录、聊天记录、现场照片/视频、商家监控（可选）、第三方证人。
3. **判定结果**：支持学生（全额或补差结算 + 商家扣信用分）／支持商家（部分或不予结算 + 学生扣信用分）／双方和解（按约定金额结算）。
4. **升级**：单方 3 次投诉成立 → 进入观察期（限制接单/发单）；5 次 → 永久封禁并公示（脱敏）。

## 7. 匹配与推荐机制

### 7.1 匹配的六个核心维度

| 维度 | 说明 | 数据来源 |
| --- | --- | --- |
| 时间匹配 | 岗位时间片与学生「可工作时段」完全包含或高度重叠 | 学生档案 + 岗位时间片 |
| 地理位置 | 学生校区/常住地到门店的距离，结合通勤方式（步行/骑行/公交）估算真实耗时 | 定位 + 门店坐标 + 地图耗时 |
| 技能标签 | 岗位要求的标签（传菜、收银、促销、外语、摄影、主持）与学生自评/商家认证标签的交集 | 标签体系 |
| 薪资匹配 | 岗位时薪是否 ≥ 学生期望时薪 | 学生档案 |
| 信用与履约 | 信用分、履约率、爽约次数、投诉记录是否满足岗位门槛 | 信用体系 |
| 历史行为 | 是否做过该商家、该类目、该商圈；复购与「班底」关系 | 订单历史 |

### 7.2 推荐排序规则（MatchScore）

```
MatchScore = 0.25 × 时间匹配度
           + 0.20 × 距离得分
           + 0.15 × 信用得分
           + 0.15 × 履约得分
           + 0.10 × 技能标签匹配
           + 0.10 × 薪资匹配
           + 0.05 × 活跃度/新鲜度
           + 关系加分（同商家复购 +8，同商圈 +3，朋友组队 +5）
           − 惩罚项（近 30 天取消 1 次 −10，爽约 1 次 −25）
```

**硬性过滤（先于打分）**

1. 时间冲突（与已录用订单重叠）→ 直接过滤。
2. 未满足岗位门槛（信用分、年龄、健康证、性别要求不适用则改为「体力要求」描述）→ 过滤。
3. 距离 > 学生设置上限 → 过滤。
4. 已录用未完成订单 ≥ 3 → 限制报名。

**分端排序目标**

| 端 | 排序目标函数 | 说明 |
| --- | --- | --- |
| 学生端岗位流 | 最大化「学生报名后履约完成」的期望 | 不只是点击率，而是完成率 |
| 商家端报名列表 | 最大化「录用后到岗且评价良好」的期望 | 突出履约率与同类经验 |
| 平台整体 | 最大化**每小时有效工时成交量** | 北极星的直接抓手 |

**反马太效应与曝光分配**

- 新学生扶持：注册 14 天内、完成认证的用户，前 3 次报名获得曝光加权 +15%。
- 新商家扶持：前 3 个岗位免费进入「新店专区」并推送至匹配学生。
- 高信用学生限流保护：同一学生每日被推送岗位数上限 30 条，避免疲劳与抢单垄断。
- 冷门岗位保护：发布 6 小时仍 0 报名的岗位，自动扩大距离半径 1.5 倍并降低门槛提示。

### 7.3 消息通知与订阅机制

| 类型 | 触发条件 | 渠道 | 频控 |
| --- | --- | --- | --- |
| 订阅提醒 | 学生设置的「时间片 + 类目 + 距离 + 时薪」命中新岗位 | 微信服务通知 | 每类目每天 ≤ 3 条，合并推送 |
| 报名结果 | 录用/拒绝/候补 | 服务通知 + 站内 | 即时 |
| 到岗提醒 | T-24h 确认、T-2h 出发 | 服务通知 | 每单 2 次 |
| 结算通知 | 打款成功/失败 | 服务通知 | 即时 |
| 审批通知（商家） | 认证通过/驳回、岗位审核结果 | 服务通知 | 即时 |
| 运营触达 | 急招专区、周末精选、活动补贴 | 公众号/服务通知 | 每人每周 ≤ 2 条 |

**订阅设计要点**：学生用「时间片订阅」而非关键词订阅（更符合兼职决策逻辑）；默认开启「本周末高匹配岗位」；提供一键退订与免打扰时段。

### 7.4 抢单、报名、邀请、派单的模式选择

| 模式 | 适用岗位 | 优点 | 风险 | 建议使用条件 |
| --- | --- | --- | --- | --- |
| **抢单**（先到先得） | 门槛低、标准化、急招（传菜、搬货、物料发放） | 撮合速度最快，适合 24h 内急单 | 学生盲目抢单、爽约率高 | 时薪 ≥ 建议价，要求项 ≤ 2 个，信用门槛 600+ |
| **报名 + 商家录用**（主流） | 需筛选的岗位（促销、主持、摄影、收银） | 双向选择，匹配质量高 | 商家响应慢，学生流失 | 商家须承诺 24h 内响应，超时自动提醒/降权 |
| **邀请**（商家定向） | 复购岗位、班底岗位、高要求岗位 | 履约率最高，体验最好 | 覆盖率低 | 已有历史合作或信用分 ≥ 700 |
| **派单**（平台人工） | 大额活动、特殊岗位、无人应招急单 | 兜底能力强 | 人力成本高 | MVP 期由运营兼任，V2 后可半自动化 |

**组合策略**：同一岗位可设置主模式 + 兜底模式。例如「报名 12 小时无录用 → 自动转为抢单」；「抢单 4 小时无人接 → 自动进入急招专区 + 短信触达候补池」。

## 8. 信任与安全机制

### 8.1 认证体系

| 角色 | 认证项 | 要求 | 通过标准 |
| --- | --- | --- | --- |
| 学生 | 实名认证 | 身份证号 + 姓名 + 人脸活体 | 三要素一致 |
| 学生 | 学生身份认证 | 学信网在线验证码 / 学生证 OCR（含注册章）/ 校园邮箱（.edu.cn）三选一 | 至少一项校验通过 |
| 学生 | 补充认证（P1） | 健康证、技能证书 | 影响高要求岗位准入 |
| 商家 | 主体认证 | 营业执照 OCR + 统一社会信用代码核验 | 信息一致且在营 |
| 商家 | 门店认证 | 门店照片 + 门头照 + 定位打卡（与填址偏差 ≤ 200m） | 人工审核通过 |
| 商家 | 经办人认证 | 法人身份证，或授权书 + 经办人身份证 | 大额/活动订单强制 |
| 校园组织 | 组织认证 | 学校/学院/社团证明 + 指导老师联系方式 | 人工审核，免抽佣 |

**认证等级与权益挂钩**：L1 仅实名（可浏览，不可接单）→ L2 实名 + 学生认证（可接单，单笔限额 300 元）→ L3 补充认证 + 履约 ≥ 3 单（单笔限额提升至 1000 元，可接夜间/高薪岗）。

### 8.2 信用分体系

**初始分 600 分，区间 0–1000。**

| 行为 | 分值变化 | 备注 |
| --- | --- | --- |
| 完成 1 单并获好评 | +5 | 每周上限 +20 |
| 完成 1 单无评价 | +2 | — |
| 获商家「优秀」标签 | +5 | 每周上限 +10 |
| 连续 4 周无爽约 | +10 | 月度结算 |
| 提前 ≥ 24h 取消订单 | −2 | 良性取消 |
| 12h 内取消 | −5 | — |
| 爽约（未到岗且未提前取消） | −25 | 同时扣除履约率，进入 7 天观察期 |
| 被投诉成立（态度/质量） | −15 | 累计 3 次限制接单 |
| 被投诉成立（诈骗/骚扰/安全问题） | 直接封禁 | 移交风控 |
| 恶意差评被驳回 | 对评价方扣分 | 双向约束 |

**权益映射**：< 500 分限制接单并需重新学习《兼职安全须知》；500–699 常规；700–849 可接高薪与夜间岗位、优先推荐；≥ 850 进入「金牌学生」，享免保证金、商家定向邀约、平台保险升级。

**商家信用分**同样建模：如实描述岗位、按时确认工时、及时结算加分；虚假岗位、临时取消录用、拖欠结算扣分；< 550 分降权并限制发布。

### 8.3 黑名单与双向约束

- 学生侧：可拉黑商家（不再接收其岗位）；平台侧黑名单公示（脱敏门店名 + 原因），P2 提供查询。
- 商家侧：可标记「不再合作学生」，但该标记不公开，仅影响该商家的录用建议。
- 平台侧：对刷单、传销、色情、代考、借贷导流等类目**永久封禁**并保留数据。

### 8.4 防骗、防爽约、防恶意差评

**防骗（学生保护）**

1. **资金托管**：商家发单即预付（或按信用分级先付 30%），钱不到账岗位不上线。
2. **四不一无**：不收费、不押证件、不刷单、不签贷款、无需先买物料——平台在岗位页强制展示提示语，岗位描述含违规词直接拒审。
3. **薪资透明**：强制显式展示时薪、工时、结算时间，禁止「面议」。
4. **先行赔付**：金额 ≤ 200 元的结算纠纷，平台可先行垫付后向商家追偿。
5. **黑名单库**：接入历史违规门店库，跨校共享。

**防爽约（双向）**

1. T-24h 双向确认，任一方未确认即触发候补/补位。
2. 学生爽约扣信用分并影响推荐排序；商家临时取消录用需支付 20% 补偿金。
3. 候补池机制：每个岗位维护 20% 候补名单，缺岗自动顶替。
4. 到岗激励：连续 3 次准时到岗发放小额现金奖励或优惠券。

**防恶意差评**

1. 双向盲评，48 小时后同时公开，避免报复性评价。
2. 评价需基于订单，仅完成订单可评；评价维度结构化（准时、态度、能力、沟通）。
3. 申诉通道：被评方可提交申诉，平台核查聊天与签到记录；恶意差评驳回并反向扣分。
4. 单条差评不直接大幅扣分，采用**近 20 单加权平均**，降低偶发影响。

### 8.5 安全与隐私

| 机制 | 说明 | 优先级 |
| --- | --- | --- |
| 按单意外险 | 每笔订单自动投保，保费 1–3 元由商家承担或平台补贴，保额 10–30 万 | P1（MVP 先做头部订单试点） |
| 紧急联系人 | 认证时填写，夜间/远距离岗位强制 | P1 |
| 一键求助 | 订单页常驻，直达客服并共享实时位置，可一键呼叫 110 | P0（呼叫按钮 P0，位置共享 P1） |
| 行程分享 | 生成含门店地址与联系人虚拟号的卡片，可微信分享 | P1 |
| 隐私号 | 通话与短信走虚拟号，订单结束 48h 后失效 | P1 |
| 信息最小化 | 学生只展示姓名首字 + 校区 + 信用等级，不展示宿舍楼栋与学号 | P0 |
| 位置保护 | 仅使用「到岗校验」的即时定位，不做后台持续定位 | P0 |
| 敏感场景限制 | 夜间（22:00 后）、私人住宅、KTV/酒吧类岗位限制或禁止 | P0 |
| 数据安全 | 身份证等敏感信息加密存储、访问审计、最小权限 | P0 |

### 8.6 结算纠纷处理机制

```
学生发起申诉 → 系统冻结该笔订单款项
   → 客服 24h 内介入，调取证据（签到定位、聊天记录、现场照片、商家确认记录）
   → 判定：
       ├─ 证据清晰 → 直接判定（全额/按实际工时/不予结算）
       ├─ 金额 ≤ 200 元且证据不足 → 平台先行垫付学生，再向商家追偿
       └─ 金额较大且双方僵持 → 平台按 70/30 先行分配，差额进入争议池二次核查
   → 结果通知双方 + 信用分调整 + 记录归档
   → 对判定不服 → 3 个工作日内可提交二次申诉（由不同客服复核）
```

**原则**：钱在平台手里、证据在线上、判定有时限、结果可追溯。

## 9. 冷启动与增长策略

### 9.1 试点选择

**选点标准（4 条硬指标）**

1. 有 **1–2 所万人级高校**，且校区集中（非分散多校区）。
2. 校区 3 公里内有**成熟商圈或商业街**（餐饮 + 零售 + 生活服务 ≥ 200 家门店）。
3. 周边有**可期的活动场景**（会展中心、体育场、商场大促），能制造批量用工需求。
4. 团队本地资源可达（有校园大使或商家关系）。

**推荐形态**：**「1 校 + 1 商圈」作为最小作战单元**（Single Campus Cell），跑通后复制到下一个校区，而不是一上来铺全城。

### 9.2 先拉学生还是先拉商家？

**结论：先「锁岗位」再「拉学生」，但两手交替、以岗位池为锚。**

| 阶段 | 时间 | 动作 | 目标 |
| --- | --- | --- | --- |
| 0. 种子商户 | 第 1–2 周 | BD 走访商圈，签 30–50 家商家，签订「首月免佣 + 保底推送」协议，预置 50–80 个岗位模板 | 建立岗位池（不急于上线） |
| 1. 种子学生 | 第 2–3 周 | 通过校园大使、社团、班群招募 300–500 名种子学生，完成实名 + 学生认证 | 建立供给池 |
| 2. 首轮撮合 | 第 3–4 周 | 集中释放岗位，运营人工跟单保证首单成功 | 首单成功率 ≥ 60% |
| 3. 双边放大 | 第 5–8 周 | 学生口碑带新学生，商家看到到岗率后自愿加单 | 周订单 ≥ 200 单 |

**破局关键**：**前 50 单必须人工兜底**——运营逐单跟进（确认到岗、解决冲突、催促结算），因为首批体验决定口碑。

### 9.3 增长策略矩阵

| 策略 | 具体做法 | 成本 | 优先级 |
| --- | --- | --- | --- |
| 校园大使 | 每校 3–5 名，按拉新有效认证人数 + 成单量给佣金（阶梯 3–8 元/有效学生，5–15 元/首单） | 低 | P0 |
| 社群运营 | 建立「周末单-XX 大学兼职群」，每日 18:00 推「明日急招榜」；群内专属岗位与优先录用 | 低 | P0 |
| 地推 | 食堂门口、宿舍楼下、快递点摆摊，扫码注册送奶茶券；聚焦开学季与考试周后 | 中 | P0 |
| 商家 BD | 地推式扫街，话术聚焦「免费发单 + 24 小时到岗 + 资金托管」；提供「首单不满意免服务费」 | 中 | P0 |
| 裂变 | 邀请好友注册并完成首单，双方各得 5–10 元；组队兼职（3 人成队报名优先录用） | 中 | P1 |
| 校园组织合作 | 学生会/社团/勤工助学中心合作，承接校内活动用工，免抽佣换曝光 | 低 | P0 |
| 内容种草 | 抖音/小红书「大学城兼职避坑指南」内容，导流小程序 | 低 | P1 |
| 商家转介绍 | 商家推荐同行入驻，双方各得发单额度 | 低 | P2 |
| 补贴 | 新学生首单额外 5 元奖励；新商家首单免服务费 | 中 | P1 |

### 9.4 如何提升首次撮合成功率与复购率

**首单成功率（目标 ≥ 60%）**

1. 新学生首页**只推 5 条高匹配岗位**（MatchScore ≥ 80），不展示长列表。
2. 新学生前 3 次报名，运营在后台看到后主动提醒商家「该学生为新人，建议优先录用」。
3. 商家 24h 未处理报名 → 系统提醒 + 运营电话催办；连续超时 → 降低曝光权重。
4. 首单提供「到岗陪跑」：T-2h 人工提醒 + 路线指引 + 门店对接人确认。
5. 首单完成后 2 小时内引导评价，并发放「第二单 3 元奖励」。

**复购率（目标 30 天复购 ≥ 35%）**

1. **班底机制**：商家可把满意学生加入「班底」，下次发单优先定向邀约（转化率最高）。
2. **长期周末岗**：允许发布「每周六固定岗」，签约周期 4–8 周，学生端标为「稳定岗」。
3. **信用成长可视化**：每完成一单，明确展示信用分、经验值、标签提升与解锁权益。
4. **收益目标化**：学生可设置「攒钱目标」（如 800 元买耳机），显示进度条，强化动机。
5. **商家侧复购**：显示「本月你已节省 X 小时招聘时间、到岗率 96%」的价值账单。
6. **时段习惯养成**：每周四 18:00 推送「本周末岗位精选」，形成固定决策节奏。

## 10. 商业化设计

### 10.1 收入模式全景

| 模式 | 说明 | 定价示例 | 阶段 |
| --- | --- | --- | --- |
| 交易抽佣 | 按订单金额抽取服务费 | 学生端不收费；商家端 5%–8%（MVP 首月 0%） | V1.0 |
| 急招/置顶 | 岗位在急招专区与推荐流顶部曝光 | 19.9 元/次，或 99 元/周 | MVP 试点（最重要早期收入） |
| 招聘套餐 | 包月发单额度 + 优先推荐 + 到岗保障 | 299 元/月（10 单）、899 元/月（40 单 + 专属客服） | V1.0 |
| 商家会员 | 数据看板、班底管理、批量用工工具 | 99–199 元/月 | V2.0 |
| 学生会员 | 优先推荐、信用加速、保险升级、简历导出 | 9.9 元/月（谨慎，避免过早伤害体验） | V2.0 |
| 保险分成 | 与保险公司合作按单投保的渠道分成 | 保费 1–3 元/单，分成 20%–30% | V2.0 |
| 广告 | 商圈商家品牌曝光、校园品牌推广 | CPM/CPC | V2.0 |
| 增值服务 | 学生培训课程、技能认证、兼职履历报告 | 单项 9.9–49 元 | V2.0 |
| 数据服务 | 商圈用工景气指数、薪资行情报告（脱敏） | 定制 | V2.0+ |
| 校园代理分销 | 校园大使/代理承接本地商家并分成 | 佣金 10%–20% | V1.0 |

### 10.2 阶段建议

**MVP 阶段（0–3 个月）**

- ✅ **急招/置顶小额付费**（验证商家付费意愿，不伤用户体验）
- ✅ **校园代理分销**（用佣金替代固定人力）
- ❌ 不做抽佣（先做大交易量，避免双边摩擦）
- ❌ 不做会员与广告（用户量不足，无议价能力）

**V1.0 阶段（3–9 个月）**

- ✅ 抽佣 5%–8%（首单免佣、月累计 3 单以下免佣，降低抵抗）
- ✅ 招聘套餐（锁定稳定用工商家）
- ✅ 保险合作分成

**V2.0 阶段（9–18 个月）**

- ✅ 商家会员、学生会员、广告位、数据报告、技能培训增值

**商业化原则**：**向商家收费，不向学生收取「找工作」的费用**（求职收费是校园兼职领域的信任红线）。

## 11. MVP 范围

### 11.1 MVP 只做什么

| 范围项 | 内容 |
| --- | --- |
| 地域 | 1 个校区 + 周边 3 公里商圈 |
| 岗位类目 | 仅 3 类：餐饮帮工、零售促销、活动执行 |
| 用户 | 学生端（微信小程序）+ 商家端（同一小程序切换身份）+ 平台管理端（Web 简易后台） |
| 认证 | 学生实名 + 学生证/学信网认证；商家营业执照 + 门头照 |
| 核心链路 | 发布 → 报名 → 录用 → 签到签退 → 工时确认 → 托管结算 → 双向评价 |
| 匹配 | 基于**时间片 + 距离 + 信用门槛**的规则匹配（可用人工辅助排序，不追求算法） |
| 支付 | 微信支付托管 + T+1 打款到微信零钱 |
| 客服 | 1 名兼职客服 + 工单表格（可用第三方工单工具） |
| 保险 | 不做系统化投保，仅对大型活动订单线下购买团体险 |
| 运营 | 校园大使 3–5 名 + 2 名 BD + 2 名运营（含人工兜底撮合） |

### 11.2 MVP 不做什么

- ❌ 长招/全职/实习岗位（混淆定位，增加审核成本）
- ❌ 跨城、跨校区扩张（先跑通单校模型）
- ❌ 自建 IM（先用隐私号 + 微信服务通知，P1 再补）
- ❌ 复杂信用分体系（先用「信用等级 + 履约率」两字段）
- ❌ 智能推荐算法（先用规则打分排序，人工干预兜底）
- ❌ 会员、广告、抽佣（除急招置顶外不做商业化）
- ❌ 保险系统化、职业技能培训、履历体系
- ❌ 商家数据看板（先用运营人工出周报）

### 11.3 最小可行闭环

```
商家发单（预付） → 学生报名 → 商家录用 → 学生到岗签到 → 签退 → 商家确认工时
   → 平台结算打款 → 双向评价 → 下一次匹配更准（信用与标签回流）
```

**闭环成立的判定标准**：一个学生从注册到拿到钱，**全程零线下沟通、零现金、零投诉**，且能独立完成第二单。

### 11.4 验证成功的关键指标（MVP 门槛）

| 指标 | MVP 目标值 | 判定意义 |
| --- | --- | --- |
| 周有效岗位数 | ≥ 50 个/周 | 供给是否足够支撑需求 |
| 周活跃认证学生 | ≥ 400 人 | 需求端是否被激活 |
| 报名转化率（浏览→报名） | ≥ 25% | 岗位信息是否有吸引力 |
| 录用率（报名→录用） | ≥ 55% | 匹配质量 |
| 首单撮合成功率 | ≥ 60% | 冷启动核心命题 |
| 到岗履约率 | ≥ 92% | 信任机制是否有效 |
| 结算准时率 | 100%（T+1） | 资金托管的承诺兑现 |
| 30 天复购率 | ≥ 30% | 是否形成习惯 |
| 投诉率 | ≤ 3% | 体验底线 |
| 商家次月留存 | ≥ 50% | 供给侧是否认可价值 |
| 单均平台补贴 | ≤ 8 元并在 3 个月内下降 50% | 是否走向自运转 |

**判定逻辑**：若履约率与首单成功率达标，但商家留存不足 → 问题在供给侧价值（BD 与套餐）；若商家留存好但学生复购低 → 问题在岗位质量与信任体验。

## 12. 关键指标

### 12.1 北极星指标

> **北极星指标：每周成功履约并完成结算的工时数（Verified Shift Hours per Week，VSHW）**

理由：它同时约束了三件事——**真实用工需求（商家愿意付钱）、真实供给（学生愿意到岗）、真实履约（平台机制有效）**。任何刷量、虚假岗位、爽约都会直接拉低该指标，难以被单一维度指标掩盖。

**辅助校验指标**：撮合成功率 × 履约率 × 复购率（三者乘积 ≥ 0.15 视为健康）。

### 12.2 分层指标体系

| 层级 | 指标 | 定义 | 早期目标 |
| --- | --- | --- | --- |
| 学生端 | 注册→认证转化率 | 完成实名+学生认证 / 注册 | ≥ 55% |
| | 周活跃率（WAU/认证用户） | 每周有浏览或报名的比例 | ≥ 40% |
| | 人均周报名数 | 报名数 / 周活跃学生 | ≥ 1.5 |
| | 首单达成时长 | 注册到首单完成的中位时间 | ≤ 5 天 |
| | 30 天复购率 | 30 天内完成 ≥ 2 单的比例 | ≥ 30% |
| | 学生留存（次周） | 次周仍活跃 | ≥ 35% |
| 商家端 | 发布岗位数/周 | — | ≥ 50 |
| | 岗位报名数（每岗） | 报名数 / 岗位 | ≥ 4 |
| | 到岗率 | 实际签到 / 录用 | ≥ 92% |
| | 二次发单率 | 30 天内再次发布 | ≥ 50% |
| | 结算确认时长 | 签退到商家确认 | ≤ 12h |
| | 商家 NPS | 调研 | ≥ 30 |
| 平台端 | 撮合成功率 | 录用数 / 报名数 | ≥ 55% |
| | 履约完成率 | 完整走完签到-结算 / 录用 | ≥ 90% |
| | 平均匹配耗时 | 发布到首个录用的时间 | ≤ 8h |
| | 投诉率 | 投诉单 / 完成订单 | ≤ 3% |
| | 投诉 24h 解决率 | — | ≥ 85% |
| | 供需比 | 活跃学生数 / 有效岗位数 | 3–10（过低供给不足，过高需求不足） |
| 商业 | GMV（月） | 订单总金额 | 参考值 |
| | 平台收入 | 服务费 + 置顶 + 套餐 | 参考值 |
| | 抽佣率 | 收入 / GMV | 5%–8% |
| | 单均补贴后毛利 | — | 3 个月内转正 |
| | CAC / LTV | 分学生、分商家计算 | LTV/CAC ≥ 3 |

### 12.3 指标健康度预警

| 预警信号 | 可能原因 | 处置 |
| --- | --- | --- |
| 报名多、录用少（< 35%） | 商家响应慢 / 岗位要求虚高 | 强制 24h 响应、要求项 ≤ 3 个 |
| 录用到岗率下滑（< 85%） | 信用约束不足 / 岗位描述不符 | 收紧信用门槛、加强审核与签到校验 |
| 单岗报名 < 2 | 曝光不足或薪资过低 | 触发扩圈推送、薪资合规复核 |
| 投诉率 > 5% | 商家质量差 / 结算纠纷 | 暂停问题商家发单、人工盯结算 |
| 学生次周留存 < 25% | 岗位少或不匹配 | 补充类目、加大校园运营投入 |

## 13. 风险与合规

### 13.1 风险清单与应对

| 类别 | 风险描述 | 影响 | 应对建议 |
| --- | --- | --- | --- |
| 劳动用工定性 | 长期、固定、受管理地使用同一学生，可能被认定劳动关系/事实用工 | 商家与平台承担社保、经济补偿风险 | 限制单个学生对同一商家的连续用工周期（建议 ≤ 8 周、每周 ≤ 2 天）；明确「劳务/承揽」协议；提示商家不得进行考勤式长期管理 |
| 税务合规 | 学生劳务报酬的个税代扣代缴、发票开具 | 税务处罚 | 通过**持牌灵活用工/委托代征平台**结算并代扣代缴；单笔 ≤ 800 元按次免税额规则与税务顾问确认；平台留存完税凭证 |
| 保险缺失 | 学生工作中受伤，无工伤保险覆盖 | 高额赔偿与舆情 | 按单投保意外伤害险；活动类强制团体险；订单页展示保障范围 |
| 未成年人 | 16–18 岁学生参与劳动受严格限制 | 违法用工 | 平台仅开放 18 周岁以上；身份认证强制校验出生日期 |
| 隐私与数据安全 | 身份证、人脸、定位、学历等敏感信息 | 违反《个人信息保护法》《数据安全法》 | 最小必要收集、单独同意、加密存储、访问审计、明示隐私政策与第三方共享清单；人脸信息仅在认证时使用即时删除原图 |
| 岗位合规 | 刷单、传销、代考、色情、借贷、刷评 | 平台连带责任与下架风险 | 类目白名单制；关键词与图片审核；商家违规一次即封禁并留证 |
| 学生安全 | 夜间、偏僻场地、私人住宅、性骚扰 | 人身安全事故 | 禁区类目（私人住宅/KTV/酒吧）；夜间岗位白名单；行程分享与一键求助；女性安全提示与举报绿色通道 |
| 虚假信息 | 冒用营业执照、假门店、假岗位 | 诈骗与信任崩塌 | 执照核验 + 门头照 + 定位打卡 + 大额订单法人核验；首次发单人工复核 |
| 舆情与校园关系 | 学生出事故、学校禁止校外兼职宣传 | 品牌与渠道中断 | 与学校勤工助学中心建立合作，明确免责与安全承诺；预案与对外口径提前准备 |
| 资金安全 | 商家预付款与平台沉淀资金 | 资金挪用风险 | 资金存管于持牌支付机构，平台不设资金池；结算 T+1 自动化 |
| 竞争与替代 | 学校官方平台、58/兼职猫、微信群 | 用户流失 | 以「周末时间片 + 3 公里 + 托管结算」的差异化深度运营筑壁垒 |

### 13.2 平台责任边界

**平台承担**

1. 对入驻商家与学生进行**资质形式审核**，并保留审核记录。
2. 对岗位信息进行**内容审核**，发现违规立即下架。
3. 提供**资金托管与按约结算**服务。
4. 提供**争议调解**与**安全通道**（一键求助、投诉受理）。
5. 提供必要的**风险提示与安全指引**。

**平台不承担（明确写入用户协议）**

1. 不构成对学生与商家之间劳务关系的**用人单位**，不承担社保与劳动报酬连带责任（在法律允许范围内）。
2. 不对商家经营行为与学生个人行为承担**超出合理注意义务**的责任。
3. 不对线下发生的第三方侵权承担直接责任，但应配合取证与协助维权。

**免责的边界提醒**：平台收取服务费即意味着更高的注意义务，**不能以「仅提供信息」完全免责**。因此审核、留证、保险、客服响应能力是法律与商业双重必需。

### 13.3 合规文档清单（MVP 前必须完成）

- [ ] 用户服务协议（学生版 / 商家版）
- [ ] 隐私政策 + 个人信息收集清单与授权书
- [ ] 平台用工服务规则（禁止类目、信用规则、结算规则）
- [ ] 投诉与争议处理规则
- [ ] 保险说明与理赔流程
- [ ] 灵活用工结算与税务合规方案（含服务商资质核验）
- [ ] 校园合作沟通口径与安全承诺书
